## 1. О проекте: API Call vs AI Agent

В простых приложениях обращение к LLM часто сводится к единичной функции:

```text
Обычный API call:
Пользователь → fetch('https://api.../chat') → Ответ
```

В таком подходе у модели **нет памяти**: каждый запрос изолирован. Сама по себе модель в облаке (OpenAI, Anthropic, Meta и др.) не хранит состояние диалога между независимыми HTTP-запросами.

Чтобы чат функционировал связно, необходим **Агент (Agent)** — программная сущность, управляющая жизненным циклом общения:

```text
Пользователь
     ↓
┌───────────────────────────────────────────────────────────┐
│                        AGENT                              │
│                                                           │
│  ├── 1. Управление сообщениями (messages history)          │
│  ├── 2. Локальное сохранение (localStorage persistence)   │
│  ├── 3. Предварительный и фактический подсчёт токенов     │
│  ├── 4. Контроль Context Window (Overflow vs Auto-trim)   │
│  └── 5. Вызов HTTP API OpenRouter                         │
└───────────────────────────────────────────────────────────┘
     ↓
OpenRouter API (LLM)
```

**React-компоненты не вызывают OpenRouter API напрямую.** Вся работа с моделью, контекстом и историей инкапсулирована в классе `Agent`.

## 2. Архитектура и разделение ответственности

```text
src/
├── agent/                  # Ядро агента (не зависит от React)
│   ├── Agent.ts            # Класс Agent: оркестрация, вызовы API, режим контекста
│   ├── storage.ts          # Модуль сохранения и чтения localStorage
│   ├── tokenizer.ts        # Оценка токенов, ценообразование, разбор usage
│   └── types.ts            # TypeScript интерфейсы сообщений, статистики и конфигурации
│
├── components/             # React UI представление
│   ├── Chat.tsx            # Главный контейнер чата, подписка на Agent
│   ├── MessageList.tsx     # Список сообщений (User, Agent, уведомления об обрезке)
│   ├── MessageInput.tsx    # Поле ввода (Enter — отправка, Shift+Enter — перенос строки)
│   ├── TokenStats.tsx      # Панель статистики токенов и прогресс context window
│   ├── Settings.tsx        # Модальное окно настроек (API Key, модель, лимит, режим)
│   └── ModeToggle.tsx      # Переключатель стратегии (Production / Demo Overflow)
│
├── App.tsx                 # Корневой компонент
├── main.tsx                # Точка входа React DOM
└── styles.css              # Адаптивные стили (ChatGPT-стиль, тёмная тема)
```

### Принцип разделения ответственности (Separation of Concerns):
- **`Agent.ts`**: принимает сообщение от UI, валидирует, добавляет в историю, применяет выбранную стратегию контекста, отправляет запрос в OpenRouter, парсит ответ и точные токены `usage`, сохраняет историю, уведомляет подписчиков.
- **`storage.ts`**: инкапсулирует работу с браузерным `localStorage` (ключи `agent_messages`, `openrouter_api_key`, `agent_config`).
- **`tokenizer.ts`**: подсчитывает предварительные токены на базе BPE-эвристик (с учётом разницы латиницы и кириллицы), вычисляет примерную стоимость и предоставляет лимиты моделей.
- **React-компоненты**: отвечают исключительно за интерфейс ввода/вывода. Поток данных: `Agent -> State -> React -> UI`.

## 4. Настройка API Key

Приложение поддерживает **два источника** API-ключа:

### Вариант 1 — Через файл `.env` (для локальной разработки)
1. Скопируйте файл `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
2. Откройте `.env` и укажите ваш ключ OpenRouter:
   ```env
   VITE_OPENROUTER_API_KEY=sk-or-v1-xxxxxxxxxxxxxxxxxxxx
   ```
3. Перезапустите dev-сервер (`npm run dev`). Ключ подхватится автоматически.

### Вариант 2 — Через интерфейс Settings (в браузере)
1. Нажмите на кнопку **Settings** (шестерёнка в правом верхнем углу).
2. В поле **OpenRouter API Key** вставьте ваш ключ.
3. Нажмите **Save settings**.
4. Ключ сохранится в `localStorage` вашего браузера (`openrouter_api_key`). При последующих открытиях вкладки он восстановится.
5. Чтобы удалить ключ из браузера, нажмите кнопку **Clear stored API key**.

## 5. Безопасность (Security Disclaimer)

> [!WARNING]
> **Это учебное frontend-only веб-приложение.**
> 
> В чисто клиентском SPA (Single Page Application) без собственного бэкенда **API-ключ невозможно скрыть от пользователя**: любой посетитель может увидеть его в коде страницы, в `localStorage` или во вкладке Network инструментов разработчика (DevTools).
> 
> Такое хранение ключа допустимо **исключительно в учебных целях** на вашем локальном компьютере. Для реальных продакшн-систем всегда создаётся собственный защищённый бэкенд/прокси, хранящий ключ на сервере и не передающий его клиенту.

## 6. Выбор модели и кастомные модели (Model Management)

Приложение позволяет не только использовать базовые пресеты (`openai/gpt-4o-mini`, `google/gemini-2.0-flash-001` и др.), но и сохранять собственные модели OpenRouter:

### Добавление и удаление моделей в Settings
1. Откройте **Settings** (шестерёнка в шапке).
2. В блоке **Add New Model** введите идентификатор модели OpenRouter (например, `anthropic/claude-sonnet-4` или `qwen/qwen-2.5-72b-instruct`).
3. Нажмите **Add**:
   - Приложение автоматически отправляет запрос на эндпоинт `https://openrouter.ai/api/v1/model/<model_id>`.
   - Из ответа извлекается длина контекстного окна (`data.context_length`) и читаемое имя модели (`data.name`).
   - Модель сохраняется в `localStorage` (`agent_custom_models`) вместе со своим персональным размером контекста.
   - Если API вернул ошибку или модель не найдена (404), открывается форма ручного ввода лимита контекста.
4. Добавленные модели отображаются чипами с бейджем размера контекста (например, `1M ctx`).
5. Любую кастомную модель можно удалить нажатием на иконку корзины. Если удаляется текущая активная модель, агент автоматически переключается на безопасную базовую модель (`openai/gpt-4o-mini`).

### Быстрое переключение на главной странице (Header Switcher)
В верхней панели (шапке) расположен выпадающий список:
* **Default Presets** — стандартные предустановленные модели;
* **Saved Custom Models** — добавленные пользователем кастомные модели (с бейджами лимитов).

Переключение происходит **мгновенно в 1 клик**: выбранная модель сразу сохраняется в `localStorage`, в `Agent` автоматически устанавливается сохранённая длина контекста этой модели, а шкала прогресса и статистика токенов немедленно пересчитываются.

## 7. Персистентность истории (Persistence)

### Как это работает:
1. Каждое отправленное сообщение пользователя и каждый полученный ответ ассистента сохраняются в `localStorage` по ключу `agent_messages`.
2. При создании сущности `Agent` конструктор автоматически вызывает `loadMessages()` из `storage.ts`.
3. Загруженные сообщения подставляются в текущее состояние агента, а на их основе пересчитывается предварительный размер контекста.
4. Кнопка **Clear conversation** в шапке приложения удаляет сохранённые сообщения из `localStorage` и очищает память агента.

### Важный учебный вывод:
> Модель **не имеет собственной долговременной памяти**. Когда вы перезагружаете страницу и спрашиваете «Как меня зовут?», модель отвечает верно не потому, что запомнила вас на сервере OpenRouter, а потому, что класс `Agent` восстановил историю из `localStorage` и **повторно отправил весь диалог** в новом HTTP-запросе.

## 8. Подсчёт токенов (Token Counting)

В панели **Token Usage** (над полем ввода) отображаются 4 ключевые метрики:

1. **Current request** — количество токенов в текущем тексте запроса пользователя.
2. **Conversation** — сумма токенов всех сообщений (включая system prompt), которые сейчас отправляются модели.
3. **Response** — количество токенов в сгенерированном ответе модели.
4. **Total** — общее количество токенов (`Conversation + Response`).
5. **Context window progress** — шкала заполнения окна контекста (например, `486 / 8,192 tokens (6%)`).

### Estimated vs Exact Usage:
* **До получения ответа** отображаются оценочные токены (с пометкой `~`, например `~34`). Подсчёт ведётся модулем `tokenizer.ts` на основе символьно-байтовых коэффициентов BPE (с учётом повышенного расхода токенов на кириллицу и служебное обрамление ролей ChatML `~4 токена/сообщение`).
* **После завершения вызова API** объект ответа OpenRouter содержит блок `data.usage`:
  ```json
  "usage": {
    "prompt_tokens": 42,
    "completion_tokens": 19,
    "total_tokens": 61
  }
  ```
  Класс `Agent` немедленно обновляет статистику точными значениями от API, а префикс `~` убирается.

## 9. Режимы контекста: Demo Overflow vs Production

В шапке доступен переключатель **Context mode**:

### 1. Режим «Demo Overflow» (демонстрация переполнения)
* **Цель:** наглядно показать студенту, что происходит, когда длина беседы превышает предельный размер окна контекста модели (`contextWindow`).
* **Поведение:**
  * История сообщений **не сокращается** автоматически.
  * Все сообщения накапливаются и отправляются целиком.
  * При превышении лимита модель/агент возвращает реальную ошибку с указанием точного превышения:
    ```text
    Context limit exceeded.
    
    Conversation: 9,124 tokens
    Model limit: 8,192 tokens
    ```

### 2. Режим «Production» (автоматическая защита от переполнения)
* **Цель:** обеспечить бесперебойную работу чата при длинных диалогах.
* **Поведение:**
  * Если размер контекста приближается к лимиту модели, агент применяет стратегию:
    ```text
    1. Оставить System Message (инструкции агента)
    2. Оставить самые свежие сообщения (актуальный контекст)
    3. Удалить самые старые сообщения из истории
    ```
  * В интерфейсе появляется наглядное предупреждение:
    ```text
    Context was trimmed to fit the model limit (X older messages removed).
    ```

> **Примечание о продакшн-агентах:** В учебных целях здесь реализована базовая стратегия скользящего окна (*Sliding Window*). В реальных сложных системах могут дополнительно применяться:
> * **Conversation Summarization** (сжатие старых сообщений отдельной моделью);
> * **RAG / Semantic Vector Memory** (сохранение фактов в векторную базу данных и подмешивание только релевантных фрагментов);
> * **Structured State Tracking** (извлечение ключевых фактов в JSON-состояние).

## 10. Пошаговое руководство по проверке (5 тестов)

### Тест 1 — Обычный чат
1. Откройте `http://localhost:5173`.
2. В **Settings** введите валидный OpenRouter API ключ и выберите модель (например, `openai/gpt-4o-mini`).
3. Напишите: `Привет! Назови столицу Франции одним словом.`
4. Нажмите **Send**.
5. Убедитесь, что появился индикатор `Agent is thinking...`, затем ответ `Париж`, а блок **Token Usage** заполнился точными числами токенов.

---

### Тест 2 — Проверка Persistence (восстановление контекста)
1. В активном чате отправьте сообщение:
   > `Меня зовут Алексей. Запомни это.`
2. Дождитесь подтверждения от ассистента.
3. Полностью обновите страницу в браузере (нажмите `F5` / `Ctrl+R`) или остановите и перезапустите Vite (`npm run dev`).
4. **Проверка 1:** Убедитесь, что старые сообщения не пропали и отображаются в списке.
5. Напишите новое сообщение:
   > `Как меня зовут?`
6. **Проверка 2:** Агент ответит: «Вас зовут Алексей».
7. *Вывод:* Контекст был успешно прочитан из `localStorage` и передан в новом запросе.

---

### Тест 3 — Рост количества токенов (Token Growth)
1. Отправьте короткое сообщение: `1` → обратите внимание на значение `Conversation tokens` (например, `~25 tokens`).
2. Отправьте более длинный текст (например, абзац из 100 слов).
3. Обратите внимание, как увеличились `Current request`, `Conversation` и `Total`.
4. *Вывод:* Чем длиннее диалог, тем больше токенов отправляется при **каждом** следующем запросе, что увеличивает затраты на API.

---

### Тест 4 — Демонстрация ошибки переполнения (Demo Overflow)
1. Переключите режим в шапке на **Demo Overflow**.
2. Откройте **Settings** и для наглядности укажите маленький лимит контекста в поле **Context window**: например, `200` или `300` (можно нажать быструю кнопку `Test: 300`).
3. Нажмите **Save settings**.
4. Отправьте в чат развёрнутый вопрос или скопируйте несколько предложений текста.
5. Когда объём истории превысит 300 токенов, приложение покажет понятную карточку ошибки:
   ```text
   Context limit exceeded.
   Conversation: 384 tokens
   Model limit: 300 tokens
   ```
6. *Вывод:* В Demo-режиме история не обрезается, позволяя наглядно увидеть сбой при нехватке окна контекста.

---

### Тест 5 — Проверка режима Production (Auto-trimming)
1. Переключите режим в шапке на **Production**.
2. Оставьте лимит контекста `300` (или `800`).
3. Отправьте новое сообщение в чат.
4. **Результат:** Ошибки не возникнет! Старые сообщения будут автоматически обрезаны, а в интерфейсе появится плашка:
   `Context was trimmed to fit the model limit. Removed X older message(s)...`
5. Диалог продолжается без сбоев.

## 11. Запуск тестов и сборка

### Автоматические тесты
Проект включает автоматизированный набор тестов для `Agent`, `storage` и `tokenizer`:

```bash
npm test
```

Тестовый набор проверяет:
* Токенизацию (латиница, кириллица, оверлей ChatML, форматирование);
* Сохранение и очистку `localStorage`;
* Валидацию API-ключа;
* Формирование запроса к OpenRouter и разбор `usage`;
* Восстановление контекста после перезапуска;
* Обработку Demo Overflow;
* Автоматическую обрезку в Production Mode;
* Очистку диалога.

### Сборка для продакшна

```bash
npm run build
```

Команда компилирует TypeScript и собирает оптимизированный бандл в директорию `dist/`.
